HTTP协议

HTTP是什么

HTTP：超文本传输协议

1.1超文本

超文本是图片，文章，压缩包和超链接的集合体。

HTML就是典型的超链接。

1.2 传送

HTTP是双向的：浏览器能给网站穿请求，网站能给浏览器返回内容。

1.3 协议

协议就是双方约定好的暗号等

1.4 HTTP的模型：客户端/服务端

HTTp基于客户端/服务端：浏览器是客户端，发起请求；网站是服务端响应请求。

特点

  • 请求/响应：一次完整的对话是一次请求和一次响应
  • 无状态：HTTP默认不记事——服务器每一次对话都像是刚见面一样。（cookie/Sesssion就是在补这个短板）

二、网址丽有什么：URL深挖

完整的URL

protocol://host[:port]/path[？query][#fragent]

协议 主机 端口 路径 ？参数 #片段

部分 干什么 例子
protocol 协议名 http://
host 主机域名或IP localhost
port 端口，资源的门 8080
path 服务器上的资源路径 /blog
？query] 查询参数
#fragent 页面的片段定位 #top

其他协议

协议 作用
http:// 普通网页
https:// 加密网页
mailto: 打开邮件软件
ftp:// 传文件
file:// 打开本机文件

易错点

  • #片段：和参数容易搞混，区别：参数（？后）会发给服务器，片段**#**后只给浏览器自己用

三HTTP请求

请求的组成

3.1 请求行（第一行）

方法 空格 路径 空格 HTTP版本 回车换行

  • 方法：告诉服务器我想干什么
  • 路径：要哪个资源
  • HTTP版本 ：HTTP/1.1``HTTP/2

3.2 请求头（中间若干行）

名字：值这样的键值对每行一个是请求的附加说明HTTP/1.1里除了Host其余请求头都是可选

常见请求头 含义
Host 要去哪个网址（域名加端口）
User-Agent “我是誰”–浏览器类型，系统信息
Referer “我从哪里来”——上个页面
Cookie “我的号牌”—–之前服务器发给我的凭证
Content-Type 请求体里是什么格式（POST才有）

头不用背，知道含义以及Cookie和Content-Type这两个重要就行

3.3 空行

分界线，表示请求头结束，下面是请求体

3.4 请求体

GET里没有请求体：要的东西在URL就有了。POST有请求体：里面是提交给服务器的数据。如登录表单

四、HTTP响应

响应和请求格式差不多，都由四个部分组成

4.1 状态栏（第一行）

HTTP版本 空格 状态码 空格 状态说明比如HTTP/1.1 200 ok状态码是服务器的“表情”来表示访问成不成功等

4.2 响应头

常见响应头 作用
Content-Type 返回内容
Content-Length 内容有多长
Set-cookie 服务器发给你的号牌（记住你的关键）
Location 跳转到哪里（配合301/302使用）

4.3 空行

同上

4.4 响应体

真正返回的内容，对网页来说就是HTML源代码,再配合CSS,JS渲染页面

五、状态码

状态码是三位数字，一共无类：

类别 含义 常见例子
1xx 提示信息（中间状态少见） 100Contiune
2xx 成功：服务器处理好了 200一切正常；204成功但没内容；206分块下载/断点传续
3xx 重定向：资源挪地方了，去新地址 301永久跳转；302临时跳转；304没变，用缓存
4xx 客户端出错：你（请求）有问题 400请求格式错；403禁止访问；404找不到
5xx 服务端出错：服务器自己有问题 500服务器内部错误；502网关/代理连不上后端;503服务繁忙

常见状态码

状态码 通俗理解
200 成功，要的东西给你
301/302 跳转，去新的地址（都会在响应头Location写新地址）
403 你知道有这个东西，但不给你看
404 没有这个文件或页面
500 服务器或程序崩溃了
502 网关/代理连不上后面的后端

六、GET 与POST

HTTP的请求方式不止有两个，HTTP/1.0定义了三个GET、POST、HEAD;HTTP/1.1又加了六个:OPTIONS、PIUT、PATCH、delete、TRACE、CONNECT

方法 含义
GET 获取资源（查）
POST 提交数据、附加新内容（改、传）
HEAD 只要响应头不要内容（判断有没有）
PUT 存一个资源（整体替换）
DELETE 删一个资源
OPTIONS 问服务器支持哪些选项/方法
CONNECT 建立隧道（代理、HTTPS常用）
TRACE/PATCH TRACE：诊断回显；PATCH：局部修改

一般遇到的都是GET和POST

GET POST
干的事 要数据（查） 提交数据（改/传）
参数放哪 URL里 请求体里
能不能被收藏/缓存 能：URL里本身就是全部 不能（数据在体内）
常见的坑 参数会留在地址栏，日志里 参数在体内肉眼看不到
例子 看新闻，搜索 登录，发帖、下单

6.1 POST提交数据，怎么告诉服务器格式

Content-Type常见格式

Content-Type 干什么 例子
application/x-www-form-urlencoded 最常见的表单提交 登录表单
multipart/form-date 上传文件用的，用一串boundary边界把不同字段拆开 上传文件、头像
application/json 给接口传JSON字符串 前后端接口对接

七、Cookie与Session

7.1 cookie

类似于号牌来验证身份的

Cookie是存在浏览器里面的号牌，浏览器每次自动携带

7.2 Session

Cookie Session
存在哪 浏览器那边 服务器那边
谁在管 浏览器自带 服务器的记账本
比喻 你手里的号牌 服务员心里的账本
偷走会怎么样 号码被偷->别人能冒充你 一般碰不到
